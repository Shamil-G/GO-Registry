# GO-Registry — план улучшения проекта

Дата: 21.08.2026 · Ревизия: `cb3eda4` · Объём: ~5 700 строк Go + 11 шаблонов

## Что за проект

Внутренний сервис регистрации времени отсутствия сотрудников: chi + `html/template` + Oracle (запись через пакет `reg`), авторизация через внешний GO-SSO по IP-адресу, Prometheus-метрики, выгрузка отчётов в Excel.

Архитектурный каркас здоровый и соответствует конвенциям: единый `base.html`, `PageContext`-мидлвара с ролями в контексте, `/login`/`/logout`/`/language`/`/theme` внутри общей группы, запись в БД через PL/SQL-пакет `reg`, чтение — параметризованным SQL, `res_value` в шаблонах, lang/theme «кука как кэш, SSO как источник правды». Правки ниже — про дыры в авторизации, конкретные баги и эксплуатацию, а не про переписывание архитектуры.

Главная проблема: **проверки прав живут в меню (`home.html`), а не в хендлерах**. Половина роутов доступна любому авторизованному сотруднику напрямую по URL.

### 0.3 Подмена личности через заголовок X-Forwarded-For — СДЕЛАНО 25.08.2026, ПЕРЕСМОТРЕНО 11.09.2026

`middleware/client_ip.go` + `config/trusted_proxies.go` (`TRUSTED_PROXIES` в `.env`).

**Пересмотрено 11.09.2026 — пункты 1 и 3 ниже для нас неверны.** Ключ сессии —
вся цепочка `X-Forwarded-For` в том виде, как её собрал nginx (`клиент, прокси`),
с проверкой каждого элемента через `net.ParseIP`. В nginx остаётся
`$proxy_add_x_forwarded_for`, realip не включать. Замена ключа на `X-Real-IP`
(10.09.2026) склеила всех пользователей корпоративного прокси 192.168.1.12 в одну
сессию. Цепочку через nginx подделать нельзя: nginx дописывает настоящий адрес в
конец, клиент может добавить что-то только слева, и ключ получается новым. Дырами
были пункт 2 (доверие заголовкам без проверки источника) и отсутствие валидации —
они закрыты. Формат ключа должен совпадать во всех приложениях (Registry, Court,
SRM, SSO), менять его только везде сразу.


`middleware/page_context.go:104-106`. Сессия в SSO идентифицируется **только по IP** (`CheckSession(ctx, page.IP)`), а IP берётся из `X-Forwarded-For` целиком и без проверки:

```go
if xff := r.Header.Get("X-Forwarded-For"); xff != "" {
    return strings.TrimSpace(xff)   // вернёт "1.2.3.4, 10.0.0.1" целиком
}
```

Любой, кто может обратиться к Go-сервису мимо nginx (или через nginx, если тот не перезаписывает заголовок), подставляет `X-Forwarded-For: <IP руководителя>` и получает его сессию со всеми правами. Это самый серьёзный дефект в проекте.

Что делать:

1. ~~брать **левый** элемент цепочки, а не всю строку (`strings.Split(xff, ",")[0]`)~~ — неверно, см. выше; валидировать через `net.ParseIP` — да, каждый элемент;
2. доверять `X-Forwarded-For`/`X-Real-IP` **только если `r.RemoteAddr` принадлежит списку доверенных прокси** — список в `.env` (`TRUSTED_PROXIES`); во всех остальных случаях использовать `RemoteAddr`;
3. ~~в nginx явно поставить `proxy_set_header X-Forwarded-For $remote_addr;` (перезапись, а не append)~~ — неверно: пользователи прокси получат один ключ; оставить `$proxy_add_x_forwarded_for`;
4. отдельно обсудить с GO-Court/GO-SSO переход на cookie-сессию с подписанным токеном — привязка к IP ломается на NAT (два сотрудника за одним внешним адресом делят сессию) и не защищает от подделки в принципе.

### 0.4 (исходное описание)

| Роут | Что показывает/делает | Проверка в хендлере | Кому реально доступно |
|---|---|---|---|
| `GET /list-absent` | все отсутствующие по всему банку | **нет** | любому авторизованному |
| `GET /secure-time-off` | список службы безопасности (`status = 3`) | **нет** | любому авторизованному |
| `POST /secure-time-off` | заводит запись **на любого сотрудника** | только `IsAnonymous` | любому авторизованному |
| `GET/POST /all-list-time-off` | отсутствия по департаменту | **нет** | любому авторизованному |
| `GET /all_list_report` | тот же список в Excel | **нет** | любому авторизованному |
| `POST /del-from-list-time-off` | удаляет запись по `id` | только `IsAnonymous` | удалить **чужую** заявку |
| `POST /approve-time-off`, `/refuse-time-off` | согласование | `IsBoss` | руководитель дептА согласует заявку дептБ |
| `POST /new-message` | объявление на главной (видно анонимам) | **нет** | любому авторизованному |
| `POST /log-click` | пишет статистику с `user_name` **из тела запроса** | **нет** | подделка статистики |
| `GET /metrics` | Prometheus, вне группы и без мидлвары | **нет** | любому в сети |

В меню (`templates/home.html`) эти пункты спрятаны за `{{ if .IsAdmin }}` / `{{ if .IsBoss }}` — но это только вёрстка, а не защита.

Что делать:

- ввести хелперы `web.RequireBoss(h)`, `web.RequireAdmin(h)`, `web.RequireHR(h)` и навесить их на роут — так проверка не забудется при добавлении нового хендлера;
- в `DelFromListTimeOff`, `ApproveTimeOffPost`, `RefuseTimeOffPost` **дочитывать запись из БД по id** и сверять на сервере: удаление — только `employee = page.FIO` (или админ), согласование — только если `dep_name` записи входит в `page.SubordinateOU` / равен `page.DepName` (или админ). Одной проверки роли на входе недостаточно — это ровно тот урок, что был на GO-SRM с цепочкой из 8 хендлеров;
- `POST /new-message` закрыть `IsHR || IsAdmin`;
- `/metrics` закрыть на уровне nginx (allow только Prometheus) либо basic-auth;
- `/log-click` брать `user_name`/`dep_name` из `pageCtx`, а не из JSON тела.

### 0.5 Загрузка фото: path traversal + stored XSS

`web/new_messages.go:96-115`:

```go

safeFIO := strings.ReplaceAll(photoFIO, " ", "_")  // заменяются ТОЛЬКО пробелы
```

- `photo_fio = "../../templates/base"` + файл `x.html` → **перезапись шаблона приложения**;

Что делать: whitelist расширений (`.jpg/.jpeg/.png/.webp`), имя файла генерировать самому (`fmt.Sprintf("%d_%s%s", time.Now().Unix(), randHex(8), ext)`), проверять `http.DetectContentType` по первым 512 байтам, обернуть тело в `http.MaxBytesReader(w, r.Body, 5<<20)`, `os.MkdirAll(uploadDir, 0o755)`.

### 0.6 Нет CSRF-защиты — СДЕЛАНО 25.08.2026

`web/same_origin.go` (`RequireSameOrigin` на группе UI-роутов, `PUBLIC_HOSTS` в `.env`).


Ни одна POST-форма не несёт токена, а сессия определяется по IP — то есть любой запрос с рабочей станции сотрудника считается его запросом. Достаточно, чтобы сотрудник открыл страницу с `<form action="http://registry/approve-time-off">` и автосабмитом.

Минимальный вариант: `SameSite=Strict` на куки + проверка заголовка `Origin`/`Referer` для всех POST в отдельной мидлваре. Полный вариант: double-submit cookie с токеном в скрытом поле формы. Стоит взять то же решение, что прорабатывается в GO-Court, чтобы не расходились.

## P2 — Конвенции и архитектура

### 2.1 Шаблоны парсятся на каждый запрос

11 вызовов `ParseFiles` внутри тела обработчиков — на каждый HTTP-запрос читаются 3 файла с диска и пересобирается дерево шаблонов. Это устаревший вариант; эталон — `GO-SRM/web/templates.go` + `render_helper.go`:

- парсинг парами `(base.html, page.html [, sidebar.html])` **один раз в теле хендлер-конструктора** (`func TimeOffGet() http.HandlerFunc { tmpl := parsePageTemplate(...); return func(...){...} }`);
- парсинг с заглушечным `FuncMap` (`res_value` возвращает `""`), потому что языка запроса на этом этапе ещё нет;
- на каждый запрос — `tmpl.Clone()` + свежий `FuncMap` с реальным `i18n.Get(page.Lang, key)`;
- рендер в `bytes.Buffer`, явный `Content-Length`, потом запись в `ResponseWriter`.

Буфер уже используется везде — не хватает только выноса парсинга и `Clone()`. Заодно уйдёт копипаста ~30 строк на хендлер: сейчас блок «скомпилировать → отрендерить в буфер → отдать» повторён 11 раз почти дословно. Один `render(w, r, tmpl, data)` в `web/render_helper.go` сократит каждый хендлер вдвое.

## P3 — Эксплуатация и надёжность

- **`http.Server` без таймаутов** (`cmd/main.go:69`): нет `ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout` — медленный клиент держит соединение бесконечно. Добавить (15s/30s/60s/120s как разумный старт).
- **SSO-клиент без таймаута** (`sso/sso_client.go:60-64`, `Timeout` закомментирован): `CheckSession` вызывается на **каждом** запросе; зависший SSO подвесит весь сервис. Вернуть `Timeout: 2 * time.Second` и добавить circuit breaker или хотя бы кэш ответа `CheckSession` на 5-10 секунд по IP — это заодно снимет основную нагрузку с SSO.
- **HTTP вместо HTTPS до SSO**: `"http://" + config.Cfg.SSOServer + "/login"` — пароль сотрудника уходит по сети открытым текстом. Перевести на TLS или хотя бы зафиксировать в README, что канал считается доверенным.
- **Куки без флагов безопасности** (`web/cookies.go`): нет `HttpOnly`, `Secure`, `SameSite`. Для `lang`/`theme` риск невелик, но `SameSite=Lax/Strict` нужен как часть анти-CSRF.
- **Нет security-заголовков**: `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`. Отдельная мидлвара на 10 строк; CSP особенно важна из-за инлайновых `<style>`/`onclick` в шаблонах (их стоит вынести в `styles.css` и `static/js/`, каталог уже есть и пуст).
- **Метрики не пишут код ответа**: `middleware/metrics.go` не оборачивает `ResponseWriter`, поэтому в Grafana не видно долю 4xx/5xx. Добавить обёртку со `statusCode` и label `status`.
- **`middleware.RequestID` + `Recoverer`**: RequestID не подключён, в логах невозможно связать строки одного запроса. Подключить и класть в контекст/логгер.
- **Падение Oracle не фатально** (`cmd/main.go:63`) — сервис поднимается «автономно» и отдаёт 500 на каждой странице. Либо не стартовать, либо отдавать понятную страницу «сервис временно недоступен».
- **Логи**: `logs/registry.log` открывается в `initLogger` (не используется) и в `logging.Init`; ротация через lumberjack есть — проверить, что `error.log` тоже ротируется.
